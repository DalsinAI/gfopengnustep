# GFOS native libffi 3.8.1 port

Upstream: https://github.com/libffi/libffi tag v3.8.1 (`a09b362a01e17842184732223184253986c2cc4e`). Apply `patches/libffi/0001-m68k-amiga-exec-cacheclear-aout.patch` to that upstream tree (with `patch -p1`), run `./autogen.sh`, and configure for `--host=m68k-amigaos --build=x86_64-pc-linux-gnu --disable-shared --enable-static` using our OpenAmigaGCC 16 m68k-amigaos compiler, linker and archive tools. Include GFOpenNDK headers (`CPATH=/path/to/ndk-include.vendor`), then `make -j4 && make install` to an isolated target prefix. The patch replaces Linux cacheflush syscalls with native Exec `CacheClearE` and aligns assembly symbols with AmigaOS a.out.

`tests/ffi_smoke.c` uses real `ffi_prep_cif`/`ffi_call` integer and double calls. Expected guest output: `GFOS_FFI_PASS int=20 double=4.375`. It **cross-compiled and linked**, but has NOT been run in a GFOS guest. Confirm on real AmigaOS 3.2.3/AROS as applicable, and add a trampoline/closure invocation test before claiming full libffi qualification. This build is a dependency for GNUstep Base `NSInvocation`, not a finished Foundation port.

## Critical 68040 FPU guest fix, 18 November 2026

The originally published v0.1.0-rc1 static libffi was compiled with default m68k CFLAGS; while the integer `ffi_call` passed, the **double-return guest test failed** (`FFI_DOUBLE_FAIL 0.00000000`, exit 5) because m68k `sysv.S` follows the `__HAVE_68881__` path only when the target compiler enables the hardware FPU. Rebuild **both C and assembly** with target `-m68040 -m68881` flags. Supply them to libffi's configure-time `CFLAGS` (e.g. `CFLAGS='-O2 -m68040 -m68881' ./configure --host=m68k-amigaos ...`) rather than relying only on a later make override; ensure generated Makefile and the actual `sysv.S` compiler command include `-m68881`. The corrected target `libffi.a` SHA256 is `e00ba19d98ec24e706fab478a880b05ddab10f0c4bf5789950554870bb347df8`.

After rebuilding libffi and relinking the native 68040 `ffi_smoke`, the **actual AmigaChrome guest** printed `GFOS_FFI_PASS int=20 double=4.375` with shell exit code 0. See `docs/RC1-GUEST-RESULTS.md` and `tests/guest-evidence/gfos-rc1-guest-04-ffi-fpu-pass.log`. The corrected static archive is not in the original prerelease ZIP and is not yet closure-trampoline qualified.
